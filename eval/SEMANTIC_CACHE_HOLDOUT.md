# 语义缓存留出集验证（2026-11-01）

本报告验证的是需显式开启的 `SEMANTIC_CACHE_MODE=semantic` 试验模式。网站现在默认使用 `SEMANTIC_CACHE_MODE=exact`，仅对归一化后与已收录问法完全相同的问题返回缓存答案；其他问题进入 Agent 工作流。下述 `FAIL` 和误命中数字不代表默认精确匹配模式的表现。

## 这个验证的作用

阈值和过滤规则是在旧的 57 条开发问题上选出来的。再用同一批问题测试，只能说明系统适应了这些例子，不能说明新用户问法也会正确。这份留出集没有参与原先的规则和阈值选择，重点检查两件事：通用政策问题能否返回**正确**的缓存答案，以及办理业务、个人数据或答案不覆盖的问题能否**拒绝缓存**、交给 Agent。

这里的误命中比漏命中严重：漏命中只会多跑一次 Agent；误命中可能把“请退掉机票”直接回答成退票规则，导致业务没有办理。

## 方法

- 固定当时的语义匹配配置：`text-embedding-v2`、COSINE 阈值 `0.66`、10 个预置答案及其 30 个别名、现有 `is_cacheable` 规则。没有用留出集调阈值或改规则。该语义路径现在需要显式开启，默认精确匹配不会使用相似度阈值。
- [留出集](../data/airline/cache/holdout_eval.json)包含 60 条人工编写的中文问题：30 条应命中指定答案、20 条相似但不应命中的难负例、10 条无关或续聊问题。脚本会检查它们与预置问法、别名和旧开发集均无归一化文本重复；这不能排除语义或模板上的相近。
- 使用真实 DashScope `aembed_query` 生成向量，写入**临时 Milvus Lite** 集合，再逐题调用产品的 `SemanticCache.get_cache`。因此评估了实际的过滤、精确检索、向量检索和阈值判断；没有修改网站使用的 Milvus 集合或业务数据库。
- 先盲测一次，再补上验证程序的通过/失败退出码和结果元数据并原样复测。切换产品默认模式后，脚本显式指定 `semantic` 再测一次；三次结果相同。逐题记录预期答案、实际答案、命中层级、相似度和最近的缓存问句。原始数据见[首次结果](results/20261101_cache_holdout_initial.json)、[原复测结果](results/20261101_cache_holdout_final.json)和[切换默认模式后的复测结果](results/20261101_cache_holdout_semantic_opt_in.json)。

## 结果

| 指标 | 结果 |
|---|---:|
| 正例正确命中（召回率） | 13/30（43.3%） |
| 正例未命中 | 16/30 |
| 正例命中错误答案 | 1/30 |
| 难负例误命中 | 8/20 |
| 易负例误命中 | 0/10 |
| 所有缓存命中的正确比例（精确率） | 13/22（59.1%） |

例如，“请把这张还没使用的机票退掉”命中了退票规则答案，跳过了办理退票；“飞机上允许使用充电宝给手机充电吗”命中了**携带**充电宝的政策，但没有回答**使用**问题；“每位旅客能免费带几件物品进客舱”错命中了**托运**行李答案。留出集的 60 条问题都通过了现有前置规则，说明它没有覆盖这些新问法。

验证程序的默认验收条件是正确召回率至少 80%、错误答案 0 条、负例误命中 0 条；本次返回 `FAIL` 和非零退出码。80% 是后续加入的工程门槛，并非盲测前预注册的统计目标；即使不设召回率门槛，已观察到的 9 次错误返回也足以使安全检查失败。

## 与旧实验的关系

[旧阈值实验](results/20261011_cache_threshold.json)在开发集报告 27/30 正例命中、0/27 负例误命中，但当时使用 `embed_documents`（`document` 类型）生成向量。产品的 `set_cache` 和 `get_cache` 实际都调用 `aembed_query`（`query` 类型）。这两种向量不能直接混用来证明同一个阈值的线上表现。

实验脚本已改为与产品相同的 `query` 类型。[按新方法重跑开发集](results/20261101T012139572397Z_cache_threshold.json)后，在当前阈值 0.66 下是 27/30 正例正确、1/27 负例误命中；按开发集重新选出的零误命中推荐阈值是 0.69。留出集里多个错误命中的相似度高于 0.69，因此仅把阈值改为 0.69 仍不足以解决已观察到的问题。这一点是根据本次逐题相似度作出的推断，并未把 0.69 当作新的独立留出集结果。

## 复现和下一步

在项目 Python 环境中配置 `agent/.env` 的 `DASHSCOPE_API_KEY` 后，在仓库根目录运行验证脚本。脚本内部显式开启语义模式，网站仍保持默认精确模式：

```bash
python agent/scripts/cache_holdout_validation.py
```

脚本默认生成不覆盖旧结果的时间戳 JSON；`--output` 可以指定路径，`--min-recall` 可以调整召回率门槛。当前配置预期会保存结果并以退出码 1 报告不通过。

默认精确匹配模式不会进行向量相似度检索；`0.66` 阈值只在显式开启语义模式时使用。需要先解决语义模式的误命中，再用**另一份全新留出集**验收；如果根据这 60 条题修改规则或阈值，这份数据就成为开发集，不能继续充当独立最终证明。这是人工编写的定向压力测试，规模较小且全是中文；百分比不能外推为线上真实流量的错误率。本脚本重放预先生成的真实向量，因此不报告用户请求的端到端延迟。
